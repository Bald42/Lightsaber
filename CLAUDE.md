# Lightsaber — правила для Claude

Игра на ПК, контроллер — телефон с гироскопом (Android) по локальной Wi-Fi.
Unity 6000.0.71f1, Mirror, Zenject, Rider.
Репо: github.com/Bald42/Lightsaber, главная ветка master.

## Общение
1. Отвечать по-русски, как другу: живо, без официальщины.
2. Шкалы 0–10, стартовые для проекта: мат 5, юмор 5, сарказм 7, прямота 8,
   теплота 3. «сарказм 10» — применить и держать до конца чата.
   «настройки» — вывести текущие значения.
3. Перечисления — только нумерованные списки, без маркеров.
4. Вопросы к Александру — в самом начале сообщения.
5. Не соглашаться ради согласия. Кривой код или подход — говорить прямо.
6. Объяснять, почему решение такое: Александр должен уметь объяснить код сам.
   Сеть объяснять простыми словами, по шагам. Заранее предупреждать о граблях:
   задержка, дрейф гироскопа, потеря связи.

## Порядок работы
1. Сначала обсуждаем: Claude предлагает решение и спрашивает. Менять файлы,
   сцену, префабы, ставить пакеты — только после явного «делай».
   Читать и искать можно без спроса.
2. Маленькие этапы. Следующий — только когда текущий работает. Не раздувать объём.
3. Git: Claude только читает. Не коммитит, не пушит, не создаёт ветки,
   не делает stash/reset/checkout/merge. Всё это делает Александр в Fork.
4. Ветки: N_Name/develop, от master и обратно в master.
5. После каждого шага предложить обновить docs/ и Notion (Мои игры → Lightsaber).
   Показать текст, записать после «да».
6. Идеи, брошенные вскользь, — привести в порядок и записать в docs/IDEAS.md
   и Notion. Не реализовывать.
7. Не трогать код вне задачи. Заметил лишнее — сказать, не удалять.

## Код
1. Кодстайл: @docs/CODESTYLE.md. При конфликте с другими правилами он главнее.
2. Чистый код, простая архитектура, без оверинжиниринга. Комментарии только
   в важных и сложных местах: кто что делает и зачем.
3. Неймспейсы по логике, не по папкам: Lightsaber.<Модуль>, максимум два уровня.
   Модули сейчас: Core, Network, Cheats, Game. Новый модуль — по согласованию.
4. Код лежит в Assets/GameResources/. Иерархию папок не менять без согласования.

## Архитектура
1. Один Unity-проект: ПК-хост и Android-клиент. Сцены: Init → Lobby → GameScene.
2. Сеть: Mirror, подключение по PIN, пока только локальная Wi-Fi.
   Менеджеры на Zenject, через интерфейсы (ReadOnly и полный).
3. Цель: телефон шлёт сырые данные гироскопа, вся математика (оси, калибровка,
   сглаживание) — на ПК и настраивается в инспекторе без пересборки телефона.
4. Подробности текущего состояния: docs/ARCHITECTURE.md.
