# Решения

Формат: дата — что решили — почему.

1. 2026-11-14 — Одно приложение на ПК и телефон, много сцен (загрузка → лобби → игры). Общий код сетевых сообщений в одном месте.
2. 2026-11-14 — Сеть: Mirror (транспорт KCP поверх UDP). Пока только локальная Wi-Fi.
3. 2026-11-14 — Claude подключается к Unity через MCP for Unity (CoplayDev), работа через вкладку Code.
4. 2026-11-14 — Git: одна ветка на фичу (N_Name/develop) от master и обратно в master. Claude в git не пишет, только читает.
5. 2026-11-14 — Гироскоп пишем с нуля. Телефон шлёт сырые данные, конвертация осей и калибровка на ПК, чтобы настраивать в инспекторе без пересборки телефона.
6. 2026-11-14 — Неймспейсы по логике (модулю), не по папкам: Lightsaber.<Модуль>, максимум два уровня.
7. 2026-11-14 — Кодстайл берём рабочий, правки вносим по ходу (docs/CODESTYLE.md).
8. 2026-11-14 — Обсуждения и документы ведём в чате Claude, во вкладке Code — работа в редакторе Unity. Каждая фича — отдельный чат.
9. 2026-11-24 — Перевод осей гироскопа: меч = калибровка × Euler(90,0,0) × (x,y,-z,-w) × Euler(0,180,0). Euler(90,0,0) — поворот мира: у гироскопа Android небо по оси Z, у Unity по Y. В документации Unity его нет, проверен на замерах. Подбирать поправку хвата по одной позе нельзя: она умножается справа и не заменяет поворот мира, сходится только в той позе, по которой подбирали.
10. 2026-11-24 — На телефоне зафиксирована портретная ориентация: автоповорот менял то, как трактуются показания гироскопа.
11. 2026-11-28 — Игровой контент без торговых марок Star Wars: в игре нет слов Star Wars, Jedi, Sith, Lightsaber, «световой меч», нет оригинальных звуков, музыки, логотипов, шрифта-логотипа и узнаваемых персонажей. Звуки и модели свои или со свободной лицензией. «Lightsaber» — рабочее имя проекта, переименуем, только если дойдёт до публикации. Почему: некоммерческая пародия «для себя и друзей», механики не охраняются, а бренд и ассеты охраняются.
12. 2026-11-28 — Неймспейсы: Lightsaber.<Модуль>.<Подмодуль>, глубина по смыслу, до трёх уровней после Lightsaber (заменяет «максимум два уровня» из п. 6). Почему: «два уровня» читалось двояко, а глубже трёх — признак, что модуль пора делить.
13. 2026-11-28 — Оси телефона объясняем от позы «телефон на столе экраном вверх»: Z сквозь экран, Y вдоль длинной стороны к динамику, X вдоль короткой стороны. Оси приклеены к корпусу, а не к комнате. Схемы: docs/images/phone_axes.svg и docs/images/phone_poses.svg.
14. 2026-11-28 — Порядок дальше: сначала минимальный дрон на сырых данных, играем и решаем, живёт ли проект; сглаживание и предсказание по rotationRate — уже под конкретное ощущение. Звук и вибрация — сразу после первого играбельного режима. До прототипа код пишет Claude, понимание кода догоняем после.
