# Архитектура — как есть сейчас

Снято 2026-11-14 с ветки master (на ней ветка 3_ClaudeSetup/develop). Только факты из кода; гипотезы помечены словом «гипотеза».

## Сцены (Build Settings)
1. Init (индекс 0) — стартовая загрузка.
2. Lobby (индекс 1) — подключение телефона, старт игры.
3. GameScene (индекс 2) — игровая сцена, геймплейных скриптов пока нет.

В проекте лежат ещё UIEnvironment и GameSettings.lighting, в билд они не входят.

## Модули (неймспейсы)
1. Lightsaber.Core — запуск приложения: GameInstaller, AppLauncherReadOnly, LoadLobby, ScenesLoader.
2. Lightsaber.Network — роли, подключение, Mirror-менеджер, код-PIN.
3. Lightsaber.Network.UI — экраны лобби и кнопка возврата.
4. Lightsaber.Cheats — меню читов (SRDebugger), только в debug-сборках.

## Как стартует приложение
1. Init: GameInstaller (Zenject) регистрирует NetworkRoleManager, NetworkConnectionController, CustomNetworkManager (ищется в иерархии сцены), AppLauncherReadOnly. Читы — только если Debug.isDebugBuild.
2. AppLauncherReadOnly регистрируется последним: когда все менеджеры проинициализированы, он выставляет IsGameReady и шлёт событие.
3. LoadLobby ждёт это событие и грузит сцену Lobby по индексу 1.

## Роли: кто хост, кто клиент
NetworkRoleManager определяет роль при старте:
1. В редакторе: клон ParrelSync — клиент (телефон), основной редактор — хост (ПК).
2. Билд под Android/iOS — клиент.
3. Остальные билды (Windows) — хост.

Хост при старте сам поднимает Mirror-хост (NetworkConnectionController.StartHost).

## Подключение по PIN
1. Хост берёт свой локальный IP, из последних двух чисел делает 4-символьный PIN (алфавит без похожих символов).
2. Клиент вводит PIN, берёт первые два числа из СВОЕГО IP, достраивает адрес хоста и подключается. Если свой IP определить не вышло — перебирает типовые подсети (192.168.1., 192.168.0., 192.168.43., 172.20.10., 127.0.0.).
3. Ограничение: работает, только если телефон и ПК в одной подсети /16. Через интернет не работает (PIN — закодированный IP).
4. В ClientLobbyView таймаут подключения 5 секунд, после него — «Host not found».
5. CustomNetworkManager только пробрасывает события Mirror (подключился/отключился). Логики спавна игроков в нём нет.

## Старт игры и возврат в лобби
1. LobbyPlayerNetwork — сетевой объект игрока в лобби. Клиент вызывает [Command] на сервере, сервер меняет сцену для всех (ServerChangeScene).
2. «Старт» в ClientLobbyView просит сменить сцену на "GameScene", «Вернуться» в ReturnToLobbyUI — на "Lobby". Названия сцен прописаны строками.

## Известные косяки (в бэклоге на рефакторинг)
1. NetworkRoleManager: using ParrelSync стоит вне #if UNITY_EDITOR. ParrelSync — редакторный пакет, поэтому, судя по всему, сборка билда на этой ветке не скомпилируется. Гипотеза, проверить сборкой. В архивной ветке 2_CreateGyroInput уже исправлено через #if.
2. Debug.LogError используется для обычного лога (SetRole).
3. Сцены грузятся по индексу (LoadLobby) и по строкам ("GameScene", "Lobby"). Хрупко: сменится порядок в Build Settings — сломается.
4. LobbyPlayerNetwork.LocalInstance — статический доступ, обходит Zenject.
5. ClientLobbyView приводит интерфейс к конкретному классу, чтобы достать GetTargetIp (метода нет в интерфейсе).
6. В ClientLobbyView зашит тестовый PIN "22FG".
7. ReturnToLobbyUI инжектит INetworkConnectionController, но не использует.
8. Нет обработки потери связи в игре (вернуться в лобби при отвале хоста).
9. PIN привязан к IP — основа для универсальной сети придётся менять.

## Архив: что было в ветке 2_CreateGyroInput/develop
Ветка оставлена как архив, не мержить. Содержала GamePlayerNetwork, GameManager (спавн меча на хосте), GyroController, TestGyro (три разных варианта чтения гироскопа), сцену TestGyro. Что вынесено из разбора (гипотезы, не проверено):
1. Конвертация осей и маска правились на телефоне и пересылались RPC — из-за этого каждое изменение требовало новой сборки на телефон.
2. В GamePlayerNetwork была закомментирована строка if (!isOwned) return; — Update крутил меч и на ПК, пока NetworkTransform приносил поворот с телефона. Две силы тянули меч в разные стороны.
3. Параметр speed в TestGyro ничего не делал (умножение компонентов кватерниона на число отменяется последующей нормализацией).
Решение: гироскоп пишем с нуля, см. DECISIONS.md.
